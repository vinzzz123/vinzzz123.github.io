Personal project · Built for the fun of it

38 NIL

Spin a club-season, draft an XI, play 38 matchdays. The name is the win condition: played 38, won 38.

Type
Passion project
Brief
My own
Stack
React 19, Vite, Node
Data
9,355 players, 660 club-seasons

Why this exists

No client, no course, no deadline. I wanted to build something where every decision was mine to get right or wrong, and where the only person I had to satisfy was me — which turns out to be a harder brief than it sounds, because nothing is ever “good enough to ship.”

It’s also the project I learned the most from. Client work rewards finishing; this one rewarded going back and doing the awkward part properly, three times, until the data reconciled. Most of what follows is that.

The idea

Land on a random club-season from any of Europe’s five major leagues — the 2003–04 Arsenal side, say, or a mid-table Bundesliga squad from FIFA 17. Draft eleven players, seven substitutes, and a manager from what that squad offers. Then play a full league season and see where you finish.

The constraint that makes it a game rather than a team builder is that you only get what the spin gives you, and rerolls are limited by difficulty — from unlimited down to none at all.

Problem one: two datasets that disagree about everything

The player pool comes from two sources. One is a FIFA/EA CSV covering ten editions, processed down to the strongest twelve clubs per league per edition. The other is a set of club-seasons I rated by hand, reaching back to 1991–92 for the eras the CSV doesn’t cover.

They agree on nothing. EA writes FC Bayern München; my file says Bayern Munich. EA writes M. Neuer; my file says Manuel Neuer. EA uses CDM and CAM; I’d used DM and AM.

Club names normalise reasonably well: strip diacritics, lowercase, drop about thirty corporate tokens (fc, ac, ssc, vfb, founding years like 1899), and most clubs collapse onto the same key. What’s left is the cases where the two sources use different languages entirely, and those need an explicit alias table. There’s no clever solution to München versus Munich; you write it down.

Players are harder, because being wrong is expensive

Every player needs one stable identity, because the id is what stops the same man being drafted twice from two different squads. Matching on surname, first initial, and nationality gets you most of the way — and then cheerfully marries the 1997 Roberto Carlos to a completely different modern Brazilian of the same name.

So the matcher checks date of birth as well: the legend’s season has to fall inside that player’s plausible career. A legend who matches inherits the real FIFA id. Everyone else gets a negative synthetic id derived from a hash of name and nationality — stable across rebuilds, guaranteed not to collide with real ids because of the sign.

The lesson. Fuzzy matching that’s 95% right is not 95% as good as matching that’s right. Every false positive is a duplicated player in someone’s squad. Adding one more independent signal — a birth date the name match can’t fake — was worth more than any amount of tuning the string comparison.

Problem two: chemistry without a fixed formation

Players can be dropped anywhere on the pitch, not just into formation slots — where you drop someone determines what position he plays. That rules out a pre-drawn link graph, because there’s no fixed shape to draw it on.

So the links are derived from the geometry instead. Sort the occupied positions vertically, split them into bands wherever there’s a real vertical gap, then:

  • link neighbours along each band
  • link each player to the nearest body in the band ahead, plus anyone close enough horizontally
  • link across two bands when both hug the same touchline — a left back and a left winger connect through the midfield

A free-form XI generates its own web. Each link is then scored: same club and same season is perfect, same club is strong, same league and same nationality is strong, either alone is weak, neither is nothing.

The decision I’m happiest with

There is no out-of-position penalty. It seems like an obvious feature and I deliberately left it out.

Every player carries fifteen positional ratings from the source data. Messi at striker is 94 because the data says he’s 94 there. Messi at centre back is 55, for the same reason. The cost of misusing a player is already priced into the number. Adding a penalty on top would charge for the same mistake twice.

The UI still flags a player as misplaced when his rating in that slot drops meaningfully below his overall — but that’s presentation. It tells you something looks wrong without pretending to be a second, independent judgement.

Problem three: a league that isn’t faked

The easy version simulates your fixtures and invents plausible numbers for everyone else. The table falls apart the moment you look closely at it.

38 NIL plays a real 20-team round-robin, mirrored for the return fixtures, and simulates every match in it — not just yours. Opponent strengths come off a fixed curve with a little jitter, then get shuffled so the same club isn’t always strong. Goals are drawn from a Poisson distribution over an exponential strength difference, with home advantage applied and the expectation clamped so nothing produces an 11–0.

Injuries happen on a per-matchday roll: the best available substitute for that slot comes in for a few weeks, or an academy player rated 62 does if the bench is exhausted. That’s what makes the seven subs a real decision rather than decoration.

All of it runs through a seeded pseudo-random generator, so a given draft always produces the same season. You can share a squad and someone else gets your result.

The part nobody sees

Six Node scripts build and maintain the data, and they’re better organised than the game itself:

ScriptJob
build-poolFIFA CSV to game pool, with position quotas so every squad has a keeper and a defence. Has an inspect mode for unfamiliar CSV schemas.
upgrade-legendsStamps stable ids and replaces coarse ratings with fifteen real positional ones. Supports a dry run.
convert-legendsMigrated the original hard-coded squad list out of the source file.
add-nationalityIdempotent — running it twice is harmless, and anything unmatched is reported rather than guessed.
build-nationalitiesMaintains a hand-curated country map of ~800 names.
check-dataReads the pool the way the game does and reports every squad missing a manager.

The data file carries a version marker for its rating order, and the game checks it on load. A stale pool fails loudly instead of silently mis-indexing every rating in the game — which is exactly the bug that would have taken a week to find.

What I’d do differently. The app is one 2,500-line file. The build scripts are properly modular and the game isn’t, which is backwards — the thing I change most often should be the easiest to navigate. I’d also write tests: the interesting functions here are pure and take simple inputs, so there was no good reason not to.

Where it lives. Nowhere public — this one runs on my machine and that’s the point. It isn’t a product and I’m not maintaining it for anyone, so I’d rather keep it as the place I go to build something properly than turn it into a thing with users and a changelog. Happy to walk through the code or run it for you in an interview.
