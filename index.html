01

Internal reporting dashboard

InternshipFull stack

A full-stack internal tool built during my internship at an international telecoms operator, replacing a repetitive manual reporting task. 02

38 NIL — football draft game

Case studyPersonal

Nobody asked for this one. Spin a club-season from any of Europe’s five major leagues, draft an XI and a manager, then play a full 38-match round-robin — every other fixture simulated too, so the table is real. 9,355 players across 660 club-seasons, merged from a hand-rated set and a FIFA CSV that spell every club and player differently. Chemistry is derived from the pitch shape rather than a fixed formation graph. It’s the project where I got to make every decision for its own sake, and the one I’d most like to be asked about.

Meeting Transcriber

Personal

Upload an MP3, get back a named, timestamped Word document. 06

Project Oracle — IDX screener

Personal

Ranks Indonesian Stock Exchange listings on a six-factor model — growth, size, valuation, quality, momentum, and catalysts — weighted toward growth and small caps. Every component score is returned alongside the total, so a ranking can be explained rather than just trusted. 07

Document extraction pipeline

Client

Tools for pulling structured data out of Indonesian tax and billing documents. The tax extractor reads BP21 withholding certificates into a twelve-column spreadsheet, using the PDF text layer where one exists and falling back to Indonesian-language OCR where it doesn’t. Fields are located by label anchors rather than page coordinates, so a form redesign doesn’t break the parser — which is the whole reason it still works.

  • Python
  • PyMuPDF
  • Tesseract
  • openpyxl

Built against real tax and billing documents — not published, for confidentiality.

The thread through my work is systems people depend on. A billing dashboard is only useful if the numbers reconcile. A member management site is only finished when it survives being deployed to shared hosting you don’t control. A tax parser is only good if it still runs after the form gets redesigned. That last one is why I anchor extraction on labels instead of coordinates — a lesson learned the expensive way.

I work across the stack because most of the interesting problems live at the seams: reconciling two datasets that disagree about spelling, keeping local and remote state consistent without duplicating records, deciding whether confidential audio should leave the machine. I care about the parts a user never sees — caching, auth, failure modes — because those are what separate a demo from a tool.
